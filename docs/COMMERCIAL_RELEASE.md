# VynxDesk Commercial Release Gate

VynxDesk may be sold, but every distributed build remains subject to
AGPL-3.0-or-later. Commercial release is allowed only after all gates below pass.

## Build identity

- Build release binaries with `VYNXDESK_RENDEZVOUS_SERVER` set to the production
  rendezvous host and `VYNXDESK_RENDEZVOUS_PUB_KEY` set to that server's public key.
- Do not publish a VynxDesk release that uses the debug RustDesk public endpoint.
- Use `com.vynxdesk.client` for public mobile and Apple package identifiers.
- Set `VYNXDESK_DEVELOPMENT_TEAM` to the distributor's Apple Developer team ID.

## Windows trust

- Sign every shipped EXE, DLL, MSI, MSIX, and installer with one consistent,
  publicly trusted code-signing identity.
- Use SHA-256 and an RFC 3161 timestamp. A self-signed certificate is acceptable
  only for local or managed-enterprise testing and fails the commercial gate.
- Sign contained binaries before signing the final installer.

Until VynxDesk has a publisher certificate, use the unsigned manual-distribution
profile. The package still contains deterministic SHA-256 hashes, legal notices,
the exact source archive and the unattended installation helper, but Windows will
show an unknown-publisher warning. Automatic update must remain disabled for these
builds because a hash file alone is not a replacement for a trusted update identity.

Run the gate after packaging:

```powershell
powershell -ExecutionPolicy Bypass -File .\res\commercial-release.ps1 `
  -ArtifactPath .\dist `
  -SourceArchive .\vynxdesk-1.5.0-source.zip
```

To sign unsigned artifacts before verification, add `-Sign` and provide a
certificate thumbprint through `-CertificateThumbprint` or the
`VYNXDESK_SIGNING_CERT_THUMBPRINT` environment variable.

For the current unsigned distribution profile, package and gate the release with:

```powershell
powershell -ExecutionPolicy Bypass -File .\res\package-windows-desktop.ps1 `
  -BuildDirectory .\flutter\build\windows\x64\runner\Release `
  -AllowUnsigned

powershell -ExecutionPolicy Bypass -File .\res\commercial-release.ps1 `
  -ArtifactPath .\dist\vynxdesk-windows-x64-<timestamp> `
  -SourceArchive .\dist\vynxdesk-1.5.0-source.zip `
  -AllowUnsigned
```

Before packaging a customer build, run the manual `Release preflight` GitHub
Actions workflow. It validates the protected rendezvous inputs, verifies that
the exact `hbb_common` gitlink can be fetched by a clean runner, runs the
RustSec scan, and performs a locked release Rust build. The workflow does not
publish an artifact. The equivalent local source and submodule check is:

```powershell
python .\scripts\check_release_contract.py `
  --require-release-env `
  --verify-hbb-remote
```

The generated package includes `install-vynxdesk.ps1`. Running it as an
administrator installs the Windows service needed for unattended access, UAC and
headless virtual-display support.

## Vynx relay and rendezvous infrastructure

Use the deployment files in `ops/relay` on the production Linux VPS. They run
the VynxDesk rendezvous (`hbbs`) and relay (`hbbr`) services with persistent key
storage and the required TCP/UDP ports. The public key generated there is embedded
into each customer build through `VYNXDESK_RENDEZVOUS_PUB_KEY`; the private key
must remain only on the server.

The first production build cannot be created until the VPS has a public DNS name,
the relay stack is started, and its public key is recorded. This is an
infrastructure prerequisite, not a licensing change.

## Android arm64 build on Windows

The Windows cross-build uses a separate `C:\vcpkg-android` installation so it
does not replace the Windows static codec packages in `C:\vcpkg`.

```powershell
powershell -ExecutionPolicy Bypass -File .\flutter\build_android_arm64_windows.ps1 `
  -RendezvousServer 'rs.example.com' `
  -RendezvousPublicKey '<32-byte-base64-public-key>'
```

The script builds only the Rust library target and stages `librustdesk.so` and
`libc++_shared.so` under the arm64 Android `jniLibs` directory. Configure the
Android release keystore before producing a signed APK or AAB.

## License and source

- Ship `LICENCE`, `NOTICE`, and `PRIVACY.md` beside the download or inside the
  installer.
- Publish the complete corresponding source archive for the exact released build.
- Preserve third-party notices and provide an SBOM generated by the release CI.
- Run `cargo audit`; the release gate rejects any active RustSec vulnerability.

Create the source archive without generated binaries, caches, or signing keys:

```powershell
powershell -ExecutionPolicy Bypass -File .\res\package-source.ps1 `
  -OutputPath .\dist\vynxdesk-1.5.0-source.zip `
  -Force
```

## External release prerequisites

- Production rendezvous/relay infrastructure and matching public key.
- Publicly trusted Windows signing identity and Apple/Android signing identities.
- Distributor legal name, support contact, hosted-service privacy terms, retention
  periods, subprocessors, and applicable consumer terms.
- Clean-machine install, update, uninstall, unattended-access, file-transfer, and
  relay-path acceptance tests on every supported operating system.

For VynxDesk Play Bridge releases, also require an assigned USB VID/PID,
production PCB/enclosure electrical validation, matching firmware/desktop
identities, and the physical-input acceptance gate in
`hardware/vynx_input_bridge/README.md`. A test-identity UF2 is never a customer
artifact.
